# Проверочный лист по безопасности данных PropDevelopment

## 1. Анализ диаграммы и описание системы PropDevelopment

На основе диаграммы C4 и описания IT-ландшафта компании были выявлены следующие компоненты системы:

### Группа сервисов для клиентов
- Витрина продаж (JavaScript, React)
- client-crm-app (SpringBoot, ElasticSearch, Dynamics CRM)
- client-mart-app (Kotlin, SpringBoot)
- client-mart-estate-app (Kotlin, SpringBoot)
- client-tour-app (Kotlin, SpringBoot)
- auth-service-1 (Keycloak)

### Группа сервисов ЖКУ
- Витрина сервисов для собственников (Mobile app iOS, Android)
- tenant-core-app (Kotlin, SpringBoot)
- CRM (Kotlin, Spring Boot)

### Финансы
- accountant-service-1 (система бухгалтерского учета)
- Active Directory (MS Active Directory)

### Дата
- Хранилище данных (Greenplum)
- DWH Хранилище (S3)

### Внешние системы
- Поставщики ресурсов ЖКХ
- Платежная система
- Государственные регистрационные органы

### Базы данных
- crm-db (MSSQL)
- crm-tenant-db (PostgreSQL)
- client-mart-db (PostgreSQL)
- client-mart-estate-db (PostgreSQL)
- client-tour-db (PostgreSQL)
- tenant-core-db (PostgreSQL)
- auth-db-1 (PostgreSQL)

## 2. Классификация данных по стандартам ISO/IEC 27001 и 27002

### 2.1. Публичные данные

Данные, предназначенные для открытого доступа и не требующие защиты от раскрытия.

**Примеры в системе PropDevelopment:**
- Каталог объектов недвижимости
- Цены на квартиры
- Планировки квартир
- Информация о жилых комплексах
- Описание услуг компании
- Контактная информация компании

**Источники:**
- client-mart-estate-app
- Витрина продаж
- Публичные разделы сайта

### 2.2. Внутренние данные

Данные для служебного пользования, раскрытие которых может негативно повлиять на деятельность компании.

**Примеры в системе PropDevelopment:**
- Данные о бронированиях недвижимости
- Результаты онлайн-туров
- Статистика по продажам
- Аналитические отчеты
- Внутренние регламенты и процедуры
- Данные о работе менеджеров
- Информация о взаимодействии с партнерами

**Источники:**
- client-tour-app и client-tour-db
- client-mart-app и client-mart-db
- Хранилище данных (Greenplum)
- BI-системы

### 2.3. Конфиденциальные данные

Персональные данные и информация, раскрытие которой может причинить существенный ущерб субъектам данных или компании.

**Примеры в системе PropDevelopment:**
- Персональные данные клиентов (ФИО, телефон, email, адрес)
- Расширенная форма клиента для онлайн-сделки
- Данные о сделках купли-продажи недвижимости
- Финансовая информация клиентов
- Персональные данные собственников
- История платежей ЖКУ
- Данные об управлении умным домом
- Информация о текущем и капитальном ремонте

**Источники:**
- client-crm-app и crm-db
- CRM (для собственников) и crm-tenant-db
- client-mart-app и client-mart-db
- tenant-core-app и tenant-core-db
- Интеграции с платежной системой
- Интеграции с поставщиками ресурсов ЖКХ

### 2.4. Секретные данные

Данные, раскрытие или утрата которых может привести к критическим последствиям для компании.

**Примеры в системе PropDevelopment:**
- Учетные данные пользователей (логины, пароли, токены доступа)
- Ключи шифрования
- Сертификаты безопасности
- Данные интеграций с государственными органами (СМЭВ)
- API-ключи внешних сервисов
- Конфигурации систем безопасности
- Финансовые данные компании
- Данные бухгалтерского учета

**Источники:**
- auth-service-1 и auth-db-1
- Active Directory
- accountant-service-1
- Конфигурационные файлы всех систем
- Системы управления ключами

## 3. Определение рисков для каждой категории данных

### 3.1. Публичные данные

#### Риск: Искажение данных
**Уровень риска:** Значительный

**Описание:**
Неправильная или устаревшая информация о недвижимости может привести к недовольству клиентов и репутационным потерям.

**Актуальность для PropDevelopment:**
В системе существует несколько точек обновления данных об объектах недвижимости. Отсутствие централизованного контроля может привести к рассогласованию данных между client-mart-estate-app и витриной продаж. Клиенты могут видеть неактуальные цены или статусы квартир.

**Последствия:**
- Жалобы клиентов на несоответствие информации
- Потеря доверия к компании
- Снижение конверсии продаж
- Дополнительная нагрузка на менеджеров по обработке жалоб

#### Риск: Некачественные данные
**Уровень риска:** Значительный

**Описание:**
Неполные, неточные или противоречивые данные о недвижимости снижают эффективность работы с клиентами.

**Актуальность для PropDevelopment:**
Данные об объектах недвижимости вводятся менеджерами вручную через client-mart-estate-app. Отсутствие валидации и контроля качества может привести к ошибкам в описаниях, планировках, характеристиках квартир.

**Последствия:**
- Неправильные решения клиентов при выборе недвижимости
- Увеличение количества отказов после просмотра
- Снижение эффективности маркетинга
- Проблемы при проведении сделок

#### Риск: Обесценивание данных
**Уровень риска:** Незначительный

**Описание:**
Устаревание публичной информации о недвижимости со временем.

**Актуальность для PropDevelopment:**
Каталог объектов регулярно обновляется по мере продажи квартир и ввода новых объектов. Риск низкий, так как данные имеют ограниченный срок актуальности и регулярно обновляются.

**Последствия:**
- Минимальные, так как данные регулярно актуализируются

### 3.2. Внутренние данные

#### Риск: Утечка данных
**Уровень риска:** Значительный

**Описание:**
Раскрытие внутренней статистики, аналитики и бизнес-процессов конкурентам или третьим лицам.

**Актуальность для PropDevelopment:**
В хранилище данных (Greenplum) собирается информация из всех систем компании. Отсутствие системного контроля доступа к DWH может привести к утечке бизнес-аналитики. Аналитики BI имеют широкий доступ к данным через Active Directory без детальной сегментации прав.

**Последствия:**
- Потеря конкурентных преимуществ
- Использование конкурентами информации о стратегии компании
- Возможный переманивание клиентов конкурентами
- Репутационные риски

#### Риск: Искажение данных
**Уровень риска:** Значительный

**Описание:**
Изменение внутренних данных о бронированиях, турах и статистике может привести к неправильным управленческим решениям.

**Актуальность для PropDevelopment:**
Данные передаются между системами через CDC (Change Data Capture) в хранилище данных. Отсутствие контроля целостности данных при передаче может привести к искажениям. Менеджеры имеют возможность изменять данные о бронированиях и турах без должного аудита.

**Последствия:**
- Неправильные управленческие решения
- Искажение отчетности
- Проблемы с планированием продаж
- Конфликты между отделами из-за несогласованных данных

#### Риск: Потеря данных
**Уровень риска:** Значительный

**Описание:**
Утрата данных о бронированиях, турах и аналитики может нарушить бизнес-процессы.

**Актуальность для PropDevelopment:**
Резервное копирование выполняется для всех баз данных, но глубина хранения резервных копий не детализирована. При сбое в процессе CDC возможна потеря данных при передаче в хранилище. Отсутствие информации о процедурах восстановления данных.

**Последствия:**
- Потеря истории взаимодействия с клиентами
- Невозможность восстановить статистику продаж
- Проблемы с формированием отчетности
- Нарушение бизнес-процессов

### 3.3. Конфиденциальные данные

#### Риск: Утечка данных
**Уровень риска:** Критический

**Описание:**
Раскрытие персональных данных клиентов и собственников третьим лицам.

**Актуальность для PropDevelopment:**
Это ключевая проблема компании. Согласно описанию, клиенты видят в личном кабинете данные других клиентов. Отсутствует системный контроль за передаваемыми данными между IT-продуктами. API партнеров (управляющих компаний) содержат категории данных с персональной информацией. Партнер из одной УК может видеть данные клиентов других УК. Недавно у конкурента произошла утечка данных.

**Последствия:**
- Штрафы по законодательству РФ о персональных данных
- Массовые жалобы клиентов
- Серьезный репутационный ущерб
- Потеря клиентов
- Судебные иски
- Возможная приостановка деятельности

#### Риск: Потеря данных
**Уровень риска:** Критический

**Описание:**
Утрата персональных данных клиентов и информации о сделках.

**Актуальность для PropDevelopment:**
Данные клиентов хранятся в нескольких базах данных (crm-db, crm-tenant-db, client-mart-db). Есть несколько точек регистрации клиента без координации. При сбое в одной из систем возможна потеря критически важных данных о сделках. Отсутствие информации о процедурах disaster recovery.

**Последствия:**
- Невозможность завершить начатые сделки
- Потеря контактов с клиентами
- Нарушение обязательств перед собственниками
- Юридические проблемы
- Штрафы регуляторов
- Невозможность предоставлять услуги ЖКУ

#### Риск: Искажение данных
**Уровень риска:** Критический

**Описание:**
Изменение персональных данных, информации о сделках или платежах.

**Актуальность для PropDevelopment:**
Отсутствует централизованный контроль за изменением персональных данных. Данные могут изменяться в нескольких системах одновременно. Интеграция с государственными органами через СМЭВ требует точности данных. Ошибки в данных о платежах ЖКУ могут привести к конфликтам с собственниками.

**Последствия:**
- Срыв сделок купли-продажи
- Проблемы с регистрацией недвижимости
- Конфликты с собственниками из-за неправильных начислений
- Финансовые потери
- Юридические проблемы
- Репутационный ущерб

#### Риск: Некачественные данные
**Уровень риска:** Значительный

**Описание:**
Неполные или неточные персональные данные клиентов затрудняют проведение сделок.

**Актуальность для PropDevelopment:**
Клиент может заполнить минимальную форму при бронировании или расширенную форму для онлайн-сделки. Отсутствие валидации может привести к некачественным данным. Несколько точек регистрации клиента без координации могут создавать дубликаты и несогласованность.

**Последствия:**
- Задержки в проведении сделок
- Необходимость повторного сбора данных
- Снижение удовлетворенности клиентов
- Дополнительная нагрузка на менеджеров

#### Риск: Обесценивание данных
**Уровень риска:** Значительный

**Описание:**
Устаревание контактных данных клиентов и собственников.

**Актуальность для PropDevelopment:**
Клиенты и собственники могут менять номера телефонов, email, адреса. Отсутствие процедур актуализации данных может привести к потере связи с клиентами.

**Последствия:**
- Невозможность связаться с клиентами
- Проблемы с уведомлениями собственников
- Снижение эффективности маркетинга
- Проблемы с предоставлением услуг ЖКУ

### 3.4. Секретные данные

#### Риск: Утечка данных
**Уровень риска:** Критический

**Описание:**
Раскрытие учетных данных, ключей шифрования или данных интеграций с госорганами.

**Актуальность для PropDevelopment:**
Используется Keycloak для аутентификации, но отсутствует информация о политиках безопасности паролей. Данные аутентификации хранятся в auth-db-1. Интеграция с государственными органами через СМЭВ требует особой защиты. Специалист по ИБ один на всю компанию, и ему не передают все решения и изменения.

**Последствия:**
- Полная компрометация системы безопасности
- Несанкционированный доступ ко всем данным компании
- Возможность мошеннических действий от имени компании
- Компрометация интеграций с госорганами
- Критический репутационный ущерб
- Возможная уголовная ответственность
- Огромные финансовые потери

#### Риск: Потеря данных
**Уровень риска:** Критический

**Описание:**
Утрата ключей шифрования, сертификатов или конфигураций безопасности.

**Актуальность для PropDevelopment:**
Отсутствует информация о процедурах резервного копирования ключей и сертификатов. При потере ключей шифрования возможна полная утрата доступа к зашифрованным данным. Отсутствие централизованного управления секретами.

**Последствия:**
- Невозможность расшифровать данные
- Полная остановка работы систем
- Невозможность восстановить доступ пользователей
- Необходимость полной переконфигурации систем
- Длительный простой бизнеса
- Огромные финансовые потери

#### Риск: Искажение данных
**Уровень риска:** Критический

**Описание:**
Изменение учетных данных, ключей или конфигураций безопасности.

**Актуальность для PropDevelopment:**
Отсутствие централизованного контроля изменений в конфигурациях безопасности. Несколько служб Active Directory для разных доменов. Изменения могут вноситься без должного аудита и контроля со стороны специалиста по ИБ.

**Последствия:**
- Компрометация системы безопасности
- Несанкционированный доступ
- Нарушение работы систем аутентификации
- Блокировка легитимных пользователей
- Остановка бизнес-процессов

#### Риск: Обесценивание данных
**Уровень риска:** Критический

**Описание:**
Компрометация ключей, токенов и сертификатов делает их непригодными для использования.

**Актуальность для PropDevelopment:**
Отсутствие информации о процедурах ротации ключей и сертификатов. При компрометации необходима срочная замена, что может привести к простою систем. Отсутствие централизованного управления жизненным циклом секретов.

**Последствия:**
- Необходимость экстренной замены всех ключей и сертификатов
- Остановка работы систем на время замены
- Риск использования скомпрометированных данных злоумышленниками
- Финансовые потери от простоя

## 4. Оценка рисков

### Шкала оценки рисков

**Критический** - риск может привести к катастрофическим последствиям для бизнеса, включая остановку деятельности, крупные штрафы, судебные иски, серьезный репутационный ущерб.

**Значительный** - риск может привести к существенным проблемам в работе, финансовым потерям, недовольству клиентов, но не критичен для выживания бизнеса.

**Незначительный** - риск имеет ограниченное влияние на бизнес, легко устраняется стандартными процедурами.

## 5. Выводы и рекомендации

### Критические проблемы, требующие немедленного решения:

1. Утечка персональных данных клиентов (клиенты видят данные других клиентов в личном кабинете)
2. Отсутствие контроля доступа к API партнеров (партнер одной УК может видеть данные других УК)
3. Отсутствие централизованного управления секретами и ключами
4. Недостаточное вовлечение специалиста по ИБ в процессы изменений

### Значительные проблемы:

1. Несколько точек регистрации клиента без координации
2. Отсутствие системного контроля за передаваемыми данными между IT-продуктами
3. Отсутствие ограничений на доступ к данным со стороны систем обработки данных
4. Недостаточная валидация и контроль качества данных

### Рекомендации:

1. Провести срочный аудит безопасности с фокусом на конфиденциальные и секретные данные
2. Внедрить централизованную систему управления доступом и идентификацией
3. Разработать и внедрить политики безопасности для API партнеров
4. Создать единую точку регистрации клиентов с централизованным управлением данными
5. Внедрить систему аудита всех изменений данных
6. Разработать процедуры disaster recovery и регулярно их тестировать
7. Усилить команду ИБ или внедрить процессы обязательного согласования изменений со специалистом по ИБ
8. Внедрить систему управления жизненным циклом секретов и ключей
9. Провести обучение сотрудников по вопросам безопасности данных
10. Внедрить системы мониторинга и обнаружения инцидентов безопасности
