# Требования к интеграции с платформой умного дома

Интеграция нашей системы PropDevelopment с внешней платформой партнера для управления домофоном и шлагбаумом.

## Требования к безопасности

Для защиты данных пользователей нужно:
- Использовать HTTPS с TLS 1.2 или выше
- Шифровать критичные данные (например, команды управления) с помощью AES-256
- Проверять подлинность запросов через HMAC-подписи
- Ограничить доступ - каждый собственник видит только свои устройства
- Передавать партнеру минимум информации (ID устройства и команду)
- Проверять права пользователя перед отправкой команды на устройство

Защита от атак:
- Проверять все входящие данные на корректность
- Ограничить количество запросов (например, 100 в минуту на одного пользователя)
- Блокировать при подозрительной активности

По персональным данным - соблюдать 152-ФЗ. Биометрические данные обрабатываются только на самих устройствах, не передаются в облако.

## Аутентификация и авторизация

Для пользователей:
- OAuth 2.0 через Keycloak
- Токены доступа живут 1 час, refresh токены - 30 дней
- Двухфакторная аутентификация (пароль + SMS или биометрия)

Между системами:
- Взаимная аутентификация по сертификатам
- API-ключи (менять раз в квартал)
- JWT токены для каждого запроса

Права доступа:
- Владелец - полный доступ к своим устройствам
- Гость - временный доступ
- Администратор - управление системой

Все действия логируются для аудита.

## Взаимодействие между системами

Наша система PropDevelopment будет взаимодействовать с платформой партнера следующим образом:

1. **Инициализация подключения**
   - При первом подключении системы обмениваются сертификатами и API-ключами
   - Устанавливается защищенное соединение через HTTPS
   - Проверяется доступность обеих систем

2. **Отправка команд от пользователя**
   - Пользователь через мобильное приложение PropDevelopment отправляет команду (например, открыть шлагбаум)
   - Наш сервер проверяет права пользователя на управление этим устройством
   - Формируется запрос с подписью HMAC и отправляется на API партнера
   - Платформа партнера проверяет подпись, выполняет команду и отправляет ответ
   - Результат возвращается пользователю

3. **Получение событий от устройств**
   - Платформа партнера отправляет события через WebSocket (например, кто-то нажал на домофон)
   - Наша система получает событие, проверяет к какой квартире относится
   - Отправляем push-уведомление владельцу
   - Сохраняем событие в истории

4. **Синхронизация данных**
   - Раз в сутки синхронизируем список устройств и их статусы
   - При добавлении нового жильца автоматически предоставляем доступ к его устройствам
   - При выезде жильца отзываем доступ

Протоколы:
- REST API для отправки команд (JSON через POST/GET)
- WebSocket для получения событий в реальном времени
- Версионирование API - /api/v1/

Пример запроса:
```json
{
  "request_id": "уникальный ID",
  "device_id": "ID устройства",
  "command": "open_gate",
  "signature": "HMAC подпись"
}
```

Ответ:
```json
{
  "request_id": "тот же ID",
  "status": "success",
  "result": {}
}
```

Требования к производительности:
- Ответ от системы партнера должен приходить не дольше 2 секунд
- Доступность сервиса - 99.9%
- При ошибке делать повторные попытки (максимум 3 раза)

Мониторинг:
- Логировать все запросы и ошибки
- Хранить логи 90 дней
- Отслеживать время отклика и доступность
