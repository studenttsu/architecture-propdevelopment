# Обоснование выбора разделов проверочного листа безопасности

## Анализ проблем и приоритетов компании PropDevelopment

На основе анализа IT-ландшафта и описания проблем компании были выявлены следующие критические области:

### 1. Ключевые проблемы безопасности

**Проблема 1: Нарушен контроль данных**
- Несколько точек регистрации клиента без координации
- Отсутствие системного контроля за передаваемыми данными между IT-продуктами
- Отсутствие ограничений на доступ к данным со стороны систем обработки данных
- Клиенты видят в личном кабинете данные других клиентов

**Проблема 2: Проблемы с API партнеров**
- Отсутствие единых политик безопасности для API
- Отсутствие системного контроля за передаваемыми данными
- Контракты API содержат персональные данные
- Партнер одной УК может видеть данные других УК

**Проблема 3: Организационные проблемы**
- Специалист по ИБ один на всю компанию
- Нарушен процесс передачи информации между командами
- Специалисту по ИБ передают не все решения и изменения

### 2. Потребности бизнеса

1. Повысить уровень удовлетворенности клиентов (устранить ошибки с отображением чужих данных)
2. Расширить направление обработки данных (BI, ML, AI)
3. Предотвратить инциденты безопасности (как у конкурента)
4. Проверить соответствие требованиям законодательства РФ

### 3. Технические особенности архитектуры

- Доменная структура с 4 доменами
- Гибридная инфраструктура (собственные серверы + облако)
- Множество баз данных (MSSQL, PostgreSQL)
- Интеграции с внешними системами (госорганы, платежные системы, УК)
- Использование CDC для передачи данных в хранилище
- Firewall для внешнего доступа
- Active Directory для аутентификации
- Keycloak для аутентификации клиентов

## Выбор разделов проверочного листа

На основе анализа проблем и приоритетов были выбраны следующие разделы:

### I. Управление доступом

**Обоснование:**
Это критически важный раздел, так как основная проблема компании связана с утечкой данных и неправильным контролем доступа. Клиенты видят данные других клиентов, партнеры имеют доступ к данным других УК. Необходимо проверить все аспекты управления доступом.

**Приоритет:** Критический

**Связь с проблемами:**
- Решает проблему отображения чужих данных в личном кабинете
- Контролирует доступ партнеров к API
- Обеспечивает принцип минимальных привилегий
- Предотвращает несанкционированный доступ

### II. Безопасность данных

**Обоснование:**
Компания работает с большим объемом персональных данных клиентов и собственников. Необходимо проверить классификацию данных, шифрование, резервное копирование и процессы управления данными. Это напрямую связано с требованиями законодательства РФ о персональных данных.

**Приоритет:** Критический

**Связь с проблемами:**
- Обеспечивает соответствие законодательству РФ
- Предотвращает утечки данных
- Контролирует качество и целостность данных
- Обеспечивает возможность восстановления данных

### III. Защита инфраструктуры

**Обоснование:**
Компания использует гибридную инфраструктуру с множеством систем и интеграций. Необходимо проверить сегментацию сети, защиту периметра, мониторинг и обнаружение атак. Это критично для предотвращения инцидентов, подобных тому, что произошел у конкурента.

**Приоритет:** Высокий

**Связь с проблемами:**
- Предотвращает внешние атаки
- Обеспечивает сегментацию между доменами
- Контролирует трафик между системами
- Защищает от DDoS и других атак

### IV. Управление инцидентами

**Обоснование:**
Учитывая недавний инцидент у конкурента и текущие проблемы с утечкой данных, необходимо проверить готовность компании к обнаружению, реагированию и восстановлению после инцидентов безопасности.

**Приоритет:** Высокий

**Связь с проблемами:**
- Обеспечивает быстрое обнаружение инцидентов
- Позволяет оперативно реагировать на угрозы
- Минимизирует ущерб от инцидентов
- Обеспечивает обучение на основе анализа инцидентов

### V. Специфические аспекты

**V.1. Интеграции и API**

**Обоснование:**
Это новый раздел, специфичный для PropDevelopment. Основная проблема компании связана с API партнеров и интеграциями с внешними системами. Необходимо детально проверить безопасность всех интеграций.

**Приоритет:** Критический

**Связь с проблемами:**
- Решает проблему с API партнеров
- Контролирует передачу данных в интеграциях
- Обеспечивает безопасность взаимодействия с госорганами
- Предотвращает утечки через внешние API

**V.2. Управление данными клиентов**

**Обоснование:**
Специфичный раздел для PropDevelopment, связанный с проблемой множественных точек регистрации клиентов и отсутствием координации между ними.

**Приоритет:** Критический

**Связь с проблемами:**
- Решает проблему несогласованности данных клиентов
- Контролирует качество персональных данных
- Обеспечивает единую точку управления данными
- Предотвращает дублирование и конфликты данных

**V.3. Безопасность мобильных приложений**

**Обоснование:**
Компания предоставляет мобильное приложение для собственников, которое управляет критичными функциями (умный дом, платежи ЖКУ). Необходимо проверить безопасность мобильной платформы.

**Приоритет:** Высокий

**Связь с проблемами:**
- Защищает данные собственников
- Обеспечивает безопасность платежей
- Контролирует доступ к умному дому
- Предотвращает компрометацию мобильных устройств
